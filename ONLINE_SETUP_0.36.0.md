# Дружеские дуэли 0.36.0

Это работающий прототип серверных дуэлей по коду комнаты. Он включает гостевые сессии, две стороны матча, выбор героя и карт, серверную проверку действий, таймер, сохранение SQLite, переподключение, сдачу и реванш. Публичный сервер пока не создан: для друзей нужен доступный адрес хостинга.

## Быстрый локальный запуск

1. Установи Node.js 24 LTS, если его нет.
2. Распакуй **всю** папку онлайн-сборки, включая `server`, `assets`, `pvp.js` и `pvp.css`.
3. Запусти `ЗАПУСТИТЬ_ОНЛАЙН.cmd` двойным щелчком либо выполни из этой папки:

   ```powershell
   node server/main.cjs
   ```

4. Открой `http://localhost:3000`, выбери героя для одиночной части, затем **Арена → Играть с другом**.
5. Для проверки на одном компьютере используй обычное и приватное окно браузера: это две независимые гостевые сессии.

Для проверки с двумя устройствами в одной домашней сети друг открывает `http://ЛОКАЛЬНЫЙ_IP_ТВОЕГО_ПК:3000`. Компьютер с сервером должен быть включён; Windows может запросить разрешение сетевого доступа. Не открывай входящий порт на роутере ради этого теста: для игры через интернет проще HTTPS-хостинг.

Командный файл сначала ищет обычный Node.js, затем может использовать уже имеющийся Node.js 24 из Codex runtime. Если не найден ни один вариант, он покажет ссылку на официальный установщик. Для другого компьютера Codex не нужен: достаточно обычного Node.js 24.

## Игра с друзьями через интернет

Для первого размещения подойдёт один Node.js-сервис с постоянным диском. Игра и API обслуживаются с **одного адреса**. GitHub Pages сам по себе этот Node.js-сервер не запускает.

### Вариант Render

1. Создай аккаунт Render и подключи репозиторий с **онлайн-сборкой**. В корне должны быть `index.html`, `pvp.js`, `pvp.css`, `assets`, `server`, `package.json`, `render.yaml`.
2. Можно создать сервис по шаблону `render.yaml` или вручную: Node runtime, версия Node 24, build command `node --version`, start command `node server/main.cjs`.
3. Для сохранения пользователей и матчей нужен постоянный диск: mount path `/var/data`; переменная `DATA_DIR=/var/data`.
4. Шаблон использует платный тариф `starter` и диск 1 GB. Проверь актуальную стоимость в интерфейсе Render перед созданием; ничего платного автоматически не создавалось.
5. После выбора имени сервиса задай `PUBLIC_ORIGIN` его полным адресом, например `https://your-game.onrender.com` — без завершающего `/`. Проверка здоровья: `/healthz`.
6. После запуска открой адрес сервиса. Создай гостевую сессию и комнату; отправь другу кнопку **«Ссылка другу»** либо восьмизначный код. Друг открывает тот же сервер, входит под своим именем и присоединяется.

Документация: [Node.js на Render](https://render.com/docs/deploy-node-express-app), [постоянные диски](https://render.com/docs/disks), [Node.js 24 и SQLite](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html).

### Docker / VPS

Из папки распакованной онлайн-сборки:

```sh
docker build -t dolbaebers-online .
docker volume create dolbaebers-state
docker run -d --name dolbaebers-online --restart unless-stopped -p 127.0.0.1:3000:3000 -v dolbaebers-state:/app/data -e PUBLIC_ORIGIN=https://your-game.example.com dolbaebers-online
```

Перед контейнером настрой HTTPS reverse proxy на свой домен. Используй один экземпляр сервиса с одним диском. Docker-конфигурация подготовлена; запуск образа в Docker в этой Windows-сессии отдельно не проверялся.

## Правила первой версии

- Шесть героев и все 52 карты из текущей игры. Выбираются пять разных карт; ещё пять общих для обоих игроков выбирает сервер.
- У всех базовые характеристики героя. PvE-предметы, активные предметы, межраундовая лавка и накопленные усиления не переносятся.
- Три карты в руке на раунд. Одно действие за ход: карта, способность героя или сосредоточение.
- Первый игрок определяется сервером. По 120 секунд на действие. Закрытие окна или пропажа связи не останавливает таймер.
- Максимум 24 раунда; затем сравнивается доля оставшегося HP. Ничья возможна.
- Есть сдача и реванш по согласию обоих игроков. Золото, рейтинг и предметы за дружеские дуэли не начисляются.

## Сессии, данные и эксплуатация

Имена гостевые и не подтверждают личность. Вход хранится в браузере, сервер хранит только хеш токена. Если очистить браузер или потерять сессию, восстановление по одному имени невозможно. Сессия действует 30 дней. Код комнаты приглашает второго игрока, а не даёт доступ к чужой руке.

SQLite находится в `DATA_DIR/pvp.sqlite`, по умолчанию `server/data/pvp.sqlite`. База, её WAL-файлы и `.env` исключены из Git. Не загружай их в публичный репозиторий. Для резервной копии останови сервис и скопируй каталог данных; не копируй только основной файл во время записи WAL.

Состояние сохраняется после каждой команды. При повторе того же `requestId` команда не разыгрывается заново. Устаревшая ревизия отклоняется; клиент обновляет бой. Скрытая рука соперника не передаётся другому игроку.

Гостевые сессии, не продлевавшиеся 30 дней, удаляются. Комнаты и журнал команд без изменений семь дней удаляются. Обновление страницы не должно сбрасывать PvE-прогресс. Это разные хранилища: локальный PvE и серверная дружеская комната.

Сервис рассчитан на небольшой закрытый тест друзей и один процесс. Перед массовым запуском нужны нагрузочный тест, управление сессиями, мониторинг, удобное восстановление аккаунта и дальнейший баланс. Для рейтингов и общей экономики потребуется отдельная серверная система прогресса.

## Проверки разработчика

```powershell
node --test server/tests/duel.test.cjs server/tests/api.test.cjs
```

Дополнительный браузерный прогон `qa/pvp-browser.cjs` находится в рабочем проекте: он использует установленный Edge и Playwright из Codex runtime. Он проверяет две реальные независимые сессии, ссылку-приглашение, готовность, перезапуск сервера, перезагрузку браузера и полный матч.
