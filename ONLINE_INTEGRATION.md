# Онлайн для 0.35.0

В сборке реализован клиент облачных сохранений. Сервер, БД, PvP, рейтинг и подбор игроков в рабочей папке отсутствуют.

## Контракт существующего клиента

Адрес API задаётся через `window.GOD_API_BASE` перед основным скриптом или в окне облака. Для публикации адрес лучше задавать при сборке. Запросы используют HTTPS; локальная разработка допускает localhost.

- `POST /api/v1/auth/telegram`: JSON `{ "init_data": "..." }`. Успешный ответ: `{ "access_token": "...", "player": { "display_name": "..." } }`.
- `GET /api/v1/save`: заголовок `Authorization: Bearer TOKEN`. Ответ: `{ "revision": 0, "data": null }` для нового игрока либо объект сохранения и его ревизия.
- `PUT /api/v1/save`: JSON `{ "revision": 7, "data": { ... } }`. Ответ: `{ "revision": 8 }`. Проверка исходной ревизии и запись новой должны быть одной атомарной операцией.
- HTTP 409 означает конфликт другого устройства; 401/403 — необходимость авторизоваться заново. Текст ошибки: строка `detail` либо `detail.message`.

Идентификатор владельца сохранения сервер должен определять из проверенной авторизации. Клиентский профиль не является доказательством владения предметами или победы. Telegram initData нужно проверять на сервере, включая подпись и свежесть; переданный клиентом display name не определяет личность.

## Перед облачным PvE

Нужны изоляция пользователей, ограничение размеров и частоты запросов, миграции схемы сохранения, резервное копирование и проверка восстановления. На хостинге настроить HTTPS и разрешённый origin игры. Проверить перенос с пустого профиля, сетевые ошибки, два устройства, истёкший токен и восстановление текущего боя.

Для общего игрового прогресса покупки, открытие сундуков, задания, награды и серверное время нужно перенести в отдельные подтверждаемые сервером операции. Нельзя принимать локально выданные предметы и золото как доверенную онлайн-экономику.

## Перед PvP

Выделить чистую боевую логику из DOM, анимаций и хранилища. Сервер хранит матч и RNG, проверяет колоду, стоимость маны, очередь действий и результат. Команды должны иметь уникальные номера и защиту от повторного выполнения. Нужны снимок состояния, переподключение, таймер хода и покупок, сдача, разрыв соединения и однократные награды.

Первый PvP-тест провести двумя клиентами с задержкой, потерей связи, повторными командами и перезапуском сервера. Отдельно определить PvP-инвентарь: текущие PvE-усиления и все активные предметы не следует автоматически переносить в рейтинговые матчи.

Технические тесты текущего облачного клиента используют имитацию ответов. Подключение к реальному Telegram-аккаунту и API не проверялось.
